# 📊 一页纸系统总结

## 系统是什么？

一个**电商智能客服系统**，能够：
- 🎯 识别用户的意图（是问产品、政策、还是订单？）
- 🔍 从知识库检索相关信息
- 🤔 判断是否有足够信心回答（不乱编瞎话）
- 💬 如果不确定，先问用户澄清问题

## 关键设计决策

### 1️⃣ 商家隔离
```
merchant_a ────┐
               ├─→ 各自独立的向量库
merchant_b ────┘   （数据完全看不到）
```

### 2️⃣ 意图驱动路由
```
用户问："这本书怎么样？"
  → 意图 = PRODUCT_INQUIRY
  → 路由到 products/ 目录的产品 CSV

用户问："怎么退货？"
  → 意图 = POLICY_INQUIRY
  → 路由到 raw_docs/ 目录的政策文档
```

### 3️⃣ 三重安全门
```
检索置信度 = 向量库找到了多相关的文件？ (0-1)
歧义度    = 用户的问题有多不清楚？ (0-1)
意图置信度 = LLM 对意图判断有多准？ (0-1)

综合 = 检索 × (1-歧义) × 意图

  > 0.6 → 直接回答（有信心）
  < 0.3 → 先澄清（没信心）
  0.3-0.6 → 部分澄清（一般般）
```

### 4️⃣ 价格/库存特殊处理
```
一般信息 ——→ 向量库（查描述、政策）
价格/库存 ——→ SQL 数据库（查实时数据）
           ↓
        混合路由器
           ↓
      选择合适的数据源
```

## 为什么价格库存问题很重要？

| 问题类型 | 用向量库？ | 问题是什么 | 解决方案 |
|---------|---------|----------|--------|
| "这本书讲什么" | ✅ | 需要语义理解 | 向量库很好 |
| "这本书多少钱" | ❌ | **需要实时数据** | 改用 SQL |
| "还有货吗" | ❌ | **需要实时更新** | 改用 SQL |
| "退货怎么退" | ✅ | 需要语义理解 | 向量库很好 |

**关键认知**：
- 向量库 = "有点相关的模糊搜索"
- SQL 数据库 = "确切的精确查询"
- 价格库存 = "精确且实时"

→ 所以需要**混合**系统！
