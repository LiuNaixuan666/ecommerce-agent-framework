Router（路由器）
  ├─ 识别"价格"关键词 → SQL 查询（实时）
  ├─ 识别"库存"关键词 → SQL 查询（实时）

1. 建立 SQL 数据库（SQLite）
2. 实装 Router（关键词提取 + 路由决策）
3. 集成混合检索层（并行查询两个数据源）
4. 在 API 中选择合适的数据源

## 🎓 反思：价格库存问题的意义

你提出"价格库存不应该在向量库里"是一个非常重要的识别：

1. **业务角度**：客户需要准确的实时数据，不是"可能相关的历史快照"
2. **技术角度**：向量库和 SQL 数据库各有所长，需要混合使用
3. **系统设计角度**：触发了"混合架构"的完整设计

这个观察让我们：
- ✅ 写了一份完整的 PRICE_INVENTORY_DESIGN.md（6.5k）
- ✅ 设计了混合路由机制
- ✅ 预留了 SQL 集成的位置
- ✅ 为 Apr 的实装做了充分准备

**这正是系统设计的精妙之处**——好的设计问题能暴露系统的真实需求。
