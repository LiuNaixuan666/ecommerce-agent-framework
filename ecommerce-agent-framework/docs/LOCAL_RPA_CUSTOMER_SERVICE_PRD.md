# 本地 RPA 电商智能客服 PRD

## 1. 产品定位

本系统定位为面向中小电商商家的本地智能客服中台。

系统不优先依赖各电商平台开放 API，而是通过自研 Local Agent / RPA Runtime 读取网页版客服窗口中的买家消息，将消息、商品上下文、订单上下文传入本地 AI 服务，再结合商家数据库、商品文档、政策文档、问答模板和历史对话生成推荐回复。

影刀等外部 RPA 工具可以作为早期验证或对照方案，但当前项目主线是自研 Local Agent：由系统自己完成消息监听、去重、回填发送、发送验证和状态回写。

第一阶段目标不是完全替代人工客服，而是先实现：

- 统一多个电商平台的客服知识与回复口径
- 降低商家分别购买各平台 AI 客服的成本
- 在本地运行，减少平台权限和数据上云依赖
- 通过自研 Local Agent 跑通“读取消息 - 生成回复 - 自动发送 - 发送结果回写”的闭环
- 低风险问题自动回复，解决不了或高风险问题再转人工
- 将转人工后的人工回复沉淀为问答模板

## 2. 目标用户

### 2.1 主要用户

- 同时经营多个电商平台的个人商家或小团队
- 商品、政策、客服话术需要跨平台复用的商家
- 暂时拿不到平台 API 权限，但希望引入 AI 客服能力的商家
- 对数据本地化有要求，不希望完整客服数据上传云端的商家

### 2.2 典型平台

- 拼多多
- 淘宝 / 天猫
- 京东
- 抖店
- 小红书
- 快手小店

## 3. 用户痛点

1. 各平台 AI 客服需要分别购买、分别配置，成本高。
2. 不同平台客服回复口径不统一，容易产生售后纠纷。
3. 平台开放 API 权限申请难、周期长、限制多。
4. 商品、库存、政策、问答模板需要重复维护。
5. 页面抓取商品和库存信息不稳定，需要接入商家自己的数据库。
6. 人工客服处理过的问题没有沉淀，类似问题反复人工回答。
7. 历史对话分散在不同平台，不便复用为上下文和知识资产。

## 4. MVP 目标

MVP 阶段验证三件事：

1. RPA 能否稳定读取平台网页版客服窗口中的买家消息。
2. 本地 AI 系统能否结合数据库和知识库生成可用回复。
3. RPA 能否将推荐回复回填到平台客服输入框并自动发送。
4. 系统能否在低置信度、高风险或信息不足时停止自动发送并转人工。

MVP 不追求：

- 直接对接所有平台 API
- 无边界地自动处理所有问题
- 复杂售后动作自动执行，例如退款、赔偿、改价、补发
- 多商家云端 SaaS 账号体系

## 5. 核心业务流程

### 5.1 RPA 辅助回复流程

1. 买家在电商平台发送消息。
2. RPA 读取当前客服会话窗口的买家消息。
3. RPA 尽量读取当前页面上下文，例如平台、商品标题、SKU、订单号。
4. RPA 调用本地后端接口提交消息。
5. 后端查询商家数据库、商品文档、政策文档、问答模板和会话上下文。
6. Agent 生成推荐回复、风险等级、是否转人工、引用来源。
7. 系统根据风险等级和置信度判断是否允许自动发送。
8. 低风险、高置信度问题由 RPA 自动填入并发送。
9. 高风险、低置信度、缺少关键信息的问题转人工。
10. 系统记录本次问答、来源、风险判断、自动发送结果和人工最终回复。

### 5.2 问答模板沉淀流程

1. AI 对某个问题置信度低，或判断需要转人工。
2. 人工客服手动回复。
3. 系统保存买家问题、商品上下文、人工回复。
4. 商家在后台确认是否将该问题加入问答模板。
5. 后续相似问题优先命中问答模板。

### 5.3 商品知识库使用流程

1. 商家上传商品说明文档、政策文档、问答模板。
2. 上传时选择文档适用范围：
   - 全店通用
   - 指定平台
   - 指定商品
   - 指定 SKU
   - 多商品文档
3. 系统解析文档、拆分 chunk，并写入 metadata。
4. 用户咨询某商品时，检索优先级为：
   - 当前商品 / SKU 的商品级知识
   - 当前平台政策
   - 店铺通用政策
   - 问答模板
   - 商家数据库
   - 外部搜索或大模型补充

## 6. 功能需求

### 6.1 RPA 接入

系统需要提供标准 HTTP 接口，供影刀 RPA 或其他 RPA 工具调用。

RPA 需要提交的数据包括：

- 平台标识
- 店铺标识
- 会话标识
- 买家消息
- 商品 ID / SKU
- 商品标题
- 订单号
- 页面上下文
- 最近几轮对话，可选

后端需要返回：

- 推荐回复
- 风险等级
- 是否允许自动发送
- 是否必须转人工
- 需要补充的信息
- 引用来源
- 置信度

### 6.2 商家数据库接入

系统需要支持本地接入商家自己的数据源。

MVP 优先支持：

- SQLite
- CSV / Excel

后续支持：

- MySQL
- PostgreSQL
- ERP API

商家需要能在可视化页面填写：

- 数据库类型
- 连接地址
- 端口
- 用户名
- 密码
- 数据库名
- 商品表名
- 字段映射

字段映射需要支持将不同商家数据库字段映射为系统标准字段：

- product_id
- sku
- title
- category
- price
- stock
- status
- description
- updated_at

### 6.3 知识库管理

系统需要支持上传并管理以下文档：

- 商品说明文档
- 多商品目录文档
- 售后政策文档
- 物流政策文档
- 平台规则文档
- 客服话术文档
- 问答模板

每个知识 chunk 需要保存 metadata：

- merchant_id
- platform
- product_id
- sku
- doc_type
- policy_scope
- source_file
- chunk_id
- created_at

### 6.4 商品绑定与多商品文档

商品级文档必须能绑定到具体商品或 SKU。

多商品文档需要支持三种处理方式：

1. 系统自动识别商品名、SKU、书名等实体并绑定。
2. 系统解析后由商家人工确认每段内容对应商品。
3. 无法确认时作为低优先级候选知识，不作为强依据回答。

### 6.5 政策管理

政策需要分层：

- 商家统一政策
- 平台特定政策
- 商品特定政策

回答优先级：

1. 商品特定政策
2. 平台特定政策
3. 商家统一政策
4. 通用客服话术

### 6.6 上下文记忆

系统需要支持三类记忆：

- 短期上下文：当前会话最近几轮消息
- 会话摘要：长对话压缩后的摘要
- 长期历史：历史对话、人工回复、常见问题

当对话超过阈值时，系统应自动生成摘要，并在后续回答中使用摘要加最近几轮消息。

### 6.7 外部搜索与来源

当商家数据库和知识库没有答案时，系统可以调用外部搜索。

外部搜索必须满足：

- 标注来源
- 不确定时明确提示
- 高风险问题不允许仅凭外部搜索自动回复
- 可由商家配置是否启用

### 6.8 前端工作台

前端需要从普通聊天 demo 演进为客服工作台。

核心区域包括：

- 当前平台
- 当前商品
- 买家消息
- AI 推荐回复
- 风险等级
- 引用来源
- 缺失信息
- 自动发送状态
- 是否转人工
- 一键复制
- RPA 回填状态

### 6.9 多平台多会话并发

系统需要支持多个平台、多个买家会话同时进入。

每条消息必须带有：

- platform
- shop_id
- session_id
- buyer_id，可选
- product_id，可选
- order_id，可选

系统处理并发消息时需要做到：

- 不同平台消息互不影响
- 不同买家会话上下文隔离
- 同一会话内消息按时间顺序处理
- 不同会话可以并行处理
- RPA 自动发送结果需要回写到对应 session

如果同一个买家短时间连续发送多条消息，系统应支持合并或排队，避免前一条还没回复完后一条又触发错误回复。

## 7. 非功能需求

### 7.1 本地优先

系统应能在商家本地电脑或本地服务器运行。

数据默认保存在本地：

- 商家数据库连接配置
- 文档知识库
- 向量库
- 对话历史
- 问答模板

### 7.2 可迁移

系统接入不同商家数据源时，不应强依赖固定数据库结构。

通过字段映射和适配器机制实现迁移。

### 7.3 可审计

每条 AI 回复需要尽量保存：

- 使用了哪些来源
- 命中了哪些模板
- 是否调用外部搜索
- 风险等级
- 人工是否修改

### 7.4 安全边界

MVP 阶段允许自动发送，但必须建立自动发送边界。

以下情况必须停止自动发送并转人工：

- 投诉
- 差评
- 退款纠纷
- 平台处罚
- 法律风险
- 赔偿承诺
- 超出政策范围的承诺
- 置信度低于阈值
- 缺少订单号、SKU、商品上下文等关键信息
- 同一会话短时间内出现多轮追问但上下文不清晰

## 8. 成功指标

MVP 阶段可以用以下指标判断产品是否跑通：

- RPA 读取消息成功率
- AI 自动回复成功率
- 自动发送成功率
- 人工修改率
- 转人工准确率
- 误自动发送率
- 知识库命中率
- 平均响应时间
- 问答模板新增数量
- 跨平台回复一致性

## 9. 当前阶段优先级

P0：

- 稳定本地问答链路
- 结构化回复输出
- 本地商家数据库模拟
- 商品知识库 metadata 绑定
- RPA HTTP 接口

P1：

- 问答模板沉淀
- 会话摘要
- 前端客服工作台
- 数据库字段映射页面

P2：

- 外部搜索
- 多平台 RPA 模板
- 高级风险控制
- ERP / 平台 API 可选接入
